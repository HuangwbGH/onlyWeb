openclaw的llm-task是干什么的，有什么用
assistant: `llm-task` 是 OpenClaw 的一个**可选插件工具**，作用是：**跑一个“只输出 JSON”的 LLM 任务，并返回结构化结果**；如果你给它 JSON Schema，它还会按 schema 校验输出。官方文档明确说它很适合工作流引擎（比如 Lobster）里加一个通用的 LLM 步骤，这样就不用为每个流程单独写 OpenClaw 代码了。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

它的典型用途是把“让模型帮你判断/抽取/归类/生成结构化内容”做成一个标准化步骤，比如：邮件意图识别、摘要提取、分类打标、生成草稿、把自然语言转成固定 JSON 字段。文档里的示例就是：给输入邮件内容，让模型返回 `intent` 和 `draft` 两个字段。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

它有几个关键特点：
- **只允许 JSON 输出**，不会要模型返回解释性文字或代码块。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))
- **本次运行不给模型暴露工具**，所以它更像一个纯推理/结构化生成步骤，不是会自己继续调工具的 agent。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))
- 返回结果在 `details.json` 里；如果提供了 `schema`，会按 schema 校验。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

你可以把它理解成一个“**结构化 LLM 小工位**”：
- 输入 `prompt`
- 可带 `input` 数据
- 可指定 `provider`、`model`、`thinking`、`temperature`、`maxTokens`、`timeoutMs`
- 可附 `schema`
- 输出固定 JSON 结果。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

它的实际价值主要在这几个场景：

1. **工作流里插一个智能判断步骤**  
   比如审批流、客服流、邮件流里，先让模型判断“这是售后/报价/投诉/普通咨询哪一类”。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

2. **把自由文本变成结构化数据**  
   比如从一段消息里抽出：客户名、需求、优先级、截止时间。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

3. **做后续自动化前的安全缓冲层**  
   因为它本身不带工具能力，所以适合先出结构化结果，再由后面的流程决定是否执行发送、发帖、命令等有副作用的动作。文档也特别提醒：有副作用的步骤前要先做审批。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

4. **减少为每个流程单独写插件/代码的成本**  
   同一套 `llm-task`，换 prompt、input、schema，就能复用到很多场景。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

如果你要启用它，需要两步：
- 在插件配置里把 `llm-task` 打开；
- 再把这个工具加入 agent 的 `tools.allow` 白名单，因为它是 `optional: true` 的工具。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))

另外还能配置默认 provider/model、允许模型白名单、最大 token、超时等；如果设置了 `allowedModels`，不在名单里的模型请求会被拒绝。 ([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task))
