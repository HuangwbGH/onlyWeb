**LLM-TASK 是一个“只做结构化 JSON 输出”的 LLM 工具插件。**  
它的作用不是像普通聊天助手那样自由回答，而是把一次 LLM 调用变成一个**可控、可校验、可嵌入工作流**的步骤。([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task?utm_source=openai))

### 它是干什么的
最适合这类场景：

- 从一段文本里提取结构化信息
- 做分类、打标签、归纳
- 生成固定格式结果
- 在工作流里加一个“AI 判断步骤”
- 给 Lobster 这类 workflow engine 提供一个单独的 LLM 节点，而不用为每个流程单独写 OpenClaw 代码。([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task?utm_source=openai))

你可以把它理解成：

> **“把大模型包装成一个只返回 JSON 的函数调用器”**

而且还能配合 **JSON Schema** 做校验，保证输出格式符合要求。([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task?utm_source=openai))

## 它和普通对话模型有什么区别

普通聊天：
- 输出可能是自然语言
- 格式不稳定
- 适合交流

LLM-TASK：
- **强制只输出 JSON**
- 不暴露 tools 给模型
- 更适合程序、自动化、工作流消费
- 输出可以按 schema 验证。([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task?utm_source=openai))

所以它更像“工作流零件”，不是“聊天界面”。

## 使用时要注意的点

文档里提了几个很重要的限制和安全点：([docs.openclaw.ai](https://docs.openclaw.ai/tools/llm-task?utm_source=openai))

1. **它是 JSON-only**
   - 模型被要求只输出 JSON
   - 不要期待它返回解释性自然语言

2. **不给模型开放 tools**
   - 这次运行里模型不能自己再调工具

3. **输出默认视为不可信**
   - 最好用 `schema` 校验
   - 尤其是要接后续自动动作时

4. **有副作用步骤前要加审批**
   - 比如 send、post、exec 之前先审核
   - 不要让结构化输出直接无审查触发危险动作

## 三、每个字段是干嘛的

### `prompt`
告诉模型它要做什么。  
这里我让它做 4 件事：

- 判断意图
- 判断优先级
- 判断是否需要回复

放原始消息内容。

### `schema`
这是重点。  
它用来强约束输出格式，保证下游流程能稳定处理。

比如：
- `intent` 只能是固定几种
- `priority` 只能是 `low/medium/high/urgent`
- `need_reply` 必须是布尔值

这就是 LLM-TASK 最有价值的地方：**输出可控**。
