### 我查到的事实
GitHub Desktop 源码里 **没有** 发现：
- `--proxy-server`
- `commandLine.appendSwitch(...)`
- `session.defaultSession.setProxy(...)`
- 也没有单独的用户代理配置项

但它确实有一段 **Git 请求代理解析逻辑**，核心意思是：

1. 它会先尝试 `resolveProxy(url)`  
   也就是让 Electron / 系统去解析当前 URL 应该走什么代理。
2. 然后把解析出来的结果，转成给 Git 子进程用的：
   - `http_proxy`
   - `https_proxy`
3. **如果环境里已经有 `ALL_PROXY` / `http_proxy` / `HTTPS_PROXY`，它就不再解析，直接跳过**

### 这说明什么
GitHub Desktop 的 Git 网络流量，实际更像是：

> **依赖 Electron/系统的代理解析结果，再注入给 Git 子进程**

所以它不是“有一个独立代理设置入口”，而是：
- 要么跟系统代理
- 要么跟启动环境变量
- 要么你从外面把代理塞进它的进程环境

### 关键结论
你要的“只让 GitHub Desktop 单独走代理”，从源码角度看，**没有发现一个现成的原生 GUI 配置口**。
