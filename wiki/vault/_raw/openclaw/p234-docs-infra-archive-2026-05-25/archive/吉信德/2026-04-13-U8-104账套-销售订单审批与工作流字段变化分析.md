## 九、当前可归纳的销售订单工作流规律

### 1. 提交动作
主要变化：
- `iverifystate: 0 -> 1`
- `cCurrentAuditor: null -> 审批人列表`
- `ufts` 变化

### 2. 审核动作

- `iverifystate: 1 -> 2`
- `cCurrentAuditor: 审批人列表 -> null`
- `iStatus: 0 -> 1`
- `cVerifier: null -> 审核人`
- `dverifydate: null -> 审核日期`
- `dverifysystime: null -> 审核系统时间`
- `SO_SOMainHistory` 新增记录
- `SO_SODetailsHistory` 新增记录

### 3. 当前结论
对于 104账套销售订单，在启用工作流时：
- **提交** 是进入审批流
- **审核** 才是完成审批、落正式审核字段、写历史表

## 十、后续建议

### 1. 如果要继续研究“正式批量审核”
应优先从 U8 应用层或客户端入口查找，而不是直接改表：
- 菜单：`SAM030201`
- 审批对象：`17`
- 工作流：`销售订单审批流程`

### 2. 如果要做 BI 或查询报表
建议将销售订单状态拆成三个阶段字段口径：
- 提交前状态
- 审批中状态
- 已审核状态

### 3. 如果后续还要继续验证其他销售订单
建议沿用本次方法：
1. 先抓提交前快照

2. 再抓提交后状态

3. 再抓审核后状态

4. 最后逐字段对比并沉淀知识文档
